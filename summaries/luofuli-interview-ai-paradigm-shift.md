# 罗福莉访谈：Agent 时代的技术范式与组织范式

> 来源：张小珺《独家对话罗福莉：AI范式已然巨变！》。访谈发生于 2026 年 3 月，文字版发布于 2026 年 4 月。本文是对访谈的结构化深度分析，不是逐字稿复刻。原始文字稿保存在 [raw/articles/luofuli-interview-ai-paradigm-shift-2026-04-24.md](../raw/articles/luofuli-interview-ai-paradigm-shift-2026-04-24.md)，网页版总结见 [luofuli-interview-analysis.html](../assets/web/luofuli-interview-analysis.html)。

## 一句话判断

这场访谈最重要的地方，不是“罗福莉怎么看 OpenClaw”，也不是“1T 模型是不是入场券”，而是她把大模型竞争从单一模型能力竞争，重新定义成了“模型、Agent 框架、后训练、组织环境、数据反馈”五个系统之间的共演竞争。换句话说，领先者不再只是训练出一个更强模型，而是构造一个能让模型持续获得任务、环境、评价、经验和组织反馈的复合系统。

## 访谈里的核心论点

1. **AI 从 Chat 时代进入 Agent 时代。** Chat 时代的核心变量是基座模型、指令对齐和问答体验；Agent 时代的核心变量变成长期任务、多轮交互、工具调用、记忆、环境反馈和执行闭环。见 [[agent-post-training-paradigm]]。
2. **Agent 能力很吃 Post-train。** 访谈反复强调，国内团队在 Pre-train 上的代差已经缩小，下一阶段赛点是 Agent 场景下 RL scaling：如何构造长程任务、还原环境、定义 reward、让模型在复杂框架中稳定执行。
3. **Agent 框架会放大中层模型。** OpenClaw 的意义不只是壳，而是通过 memory、message channel、模型编排、主动任务、多 Agent、Skills 等机制，补偿模型行动能力缺陷，让非顶尖模型也能在多数任务中接近高端模型体验。见 [[agent-framework-model-coevolution]]。
4. **Skills 是组织知识进入模型系统的新接口。** 罗福莉把 Skills 视为人主动贡献数据、沉淀业务逻辑和执行规范的方式。它补足了预训练数据里没有的内部知识、流程经验和组织上下文。
5. **竞争从模型参数转向系统效率。** 1T 基座模型被视为接近 Claude Opus 4.6 水平的入场券，但真正的领先来自更低成本、更快迭代、更好 Agent 框架和更好的后训练数据闭环。
6. **组织形态也要跟着变。** 她对“管理”的怀疑，本质上是认为新范式要求更高密度的探索、模糊容忍度和群体智能，而传统规范化管理会压制这种探索。

## 深层洞察一：OpenClaw 是“范式检测器”，不是单个产品事件

访谈中 OpenClaw 的角色很特殊。表面上，它是一个开源 Agent 框架；更深层看，它像一次范式压力测试：谁能从一个“看起来玄学、像产品包装”的东西里识别出真实技术变量，谁就更早进入下一轮竞争。

罗福莉最初也排斥 OpenClaw，认为它可能只是 Claude Code 加 IM、UI 和运营包装。但三天高强度使用后，她观察到三个层级的跃迁：第一天，它像一个更有情商和记忆的助手；第二天，它能沉淀团队建设、人员筛选、组织架构等复杂思考为 Skills；第三天，它开始帮助构造 User Agent，反过来促进 Post-train 研究数据生成。

这说明 Agent 框架的价值不是“完成某个任务”，而是让使用者发现新任务类别：从生活辅助到组织知识沉淀，再到训练数据构造。真正的产品突破经常不是把已有任务做得更快，而是改变用户对“什么可以交给机器”的想象边界。

## 深层洞察二：Agent 框架与模型不是替代关系，而是协同进化关系

访谈里最有价值的判断之一，是模型能力提升并不会让 Agent 框架失去意义。相反，模型越强，越能改造框架；框架越好，越能释放中层模型上限。这是一个双向循环：

- 高端模型如 Claude Opus 4.6 用来探索和重构 Agent 架构、memory、多 Agent workflow。
- 被重构后的框架降低了后续任务对顶尖模型的依赖。
- 中层模型接入改造后的框架后，在多数生活和轻代码任务中获得接近顶尖模型的效果。
- 使用过程中产生的新轨迹、Skills、评价和失败案例，又变成下一轮后训练数据。

这也是 [[agent-framework-model-coevolution]] 的核心：模型不是孤立地变强，而是在工具环境中变强；框架也不是静态壳层，而是被模型和用户群体持续重写的可学习外骨骼。

## 深层洞察三：Code 泛化的秘密是长程密集依赖

罗福莉解释 Code 为什么具有泛化力：真正能达到 128K 到 1M 上下文、且依赖关系密集的数据，主要是代码和书籍；但书籍信号发散，代码文件之间关联强。软件工程天然包含长程任务、环境反馈、计划、调试、回滚、测试和多轮交互，因此它不只是一个垂直任务，而是 Agent 能力的训练场。

这个判断很关键，因为它把 Coding Agent 从“程序员工具”提升为“通用 Agent 能力的孵化器”。如果一个模型能在软件工程里稳定处理长上下文、多步计划、工具调用和真实反馈，它就具备迁移到金融分析、科研、运营、办公自动化等任务的基础能力。Code 拉高上限，其他领域训练保住下限。

## 深层洞察四：后训练的赛点不是更多样本，而是环境、轨迹与 reward

访谈多次强调 Agent 的 Post-train 难点不只是收集数据，而是还原环境。普通 SFT 样本只记录“输入—输出”，但 Agent 任务真正有价值的是完整 trajectory：用户目标、环境状态、工具调用、失败修复、上下文压缩、长期记忆、多人协作和最终验证。

因此 Agent RL scaling 面临三件硬事：第一，构造足够长且多样的任务；第二，还原任务发生时的环境；第三，定义能区分“看似完成”和“真的完成”的 reward。传统 benchmark 只防止致命错误，无法评估复杂系统在真实环境中的完成度。罗福莉说可以在短暂窗口忽略 benchmark，靠体感识别质变，但进入深水区后仍需要精细评估；这说明下一阶段评测体系必须向真实任务、长期状态和执行闭环迁移。

## 深层洞察五：Skills 是后训练时代的“组织数据接口”

访谈中 Skills 的意义被低估了。罗福莉说，Skills 定义的是执行规范；这些规范往往来自企业内部流程、业务逻辑和组织经验，不可能出现在互联网预训练数据中。人通过和 Agent 共创，把隐性经验转成可复用技能文件，本质上是在主动给模型系统贡献高价值数据。

这改变了知识生产的方向：过去模型从公开互联网吸收知识；现在组织和个人可以把自己的流程、偏好、判断标准、工具链和失败经验转成 Skills，变成 Agent 的可执行上下文。Skills 不是 prompt 小技巧，而是组织智能的压缩格式。

## 深层洞察六：算力配比变化意味着研究范式变化

访谈里“3:5:1 到 3:1:1”的说法很重要。过去 Chat 时代，研究、Pre-train、Post-train 的用卡比例可能是 3:5:1，重心在预训练；Agent 时代更合理的比例可能是 3:1:1，顶尖团队预训练和后训练接近 1:1。

这不是简单的资源分配变化，而是研发风险结构变化：Pre-train 的确定性变高、差距缩小；Post-train 的不确定性变高、回报变大。谁能更快构造环境、任务、轨迹和 RL infra，谁就能在短窗口内形成代差。

## 深层洞察七：组织问题不是软话题，而是技术路线的一部分

罗福莉对组织的表述很激进：不太存在管理，规范和约束会压制创造力；环境比经验重要；后训练需要容忍模糊性。这些话不能只当管理鸡汤看。它背后对应的是 Agent 研究本身的高不确定性。

当任务边界、评估标准、数据生成方式和产品形态都在快速漂移时，组织如果过早固化流程，就会把探索空间压扁。她推动团队强制高频使用 OpenClaw，看似粗暴，本质是在快速制造共同经验和群体智能：大家在同一环境中密集试错、互相看到新用法、把想象力变成可执行探索。

这解释了为什么她强调“玩”。在范式切换早期，会玩模型的人比只会按旧流程优化指标的人更早看到能力边界，也更容易发现可 scaling 的训练方向。

## 对行业的判断

1. **模型公司与 Agent 产品公司会更深耦合。** OpenClaw 被模型公司收购的讨论说明，Agent 框架不能长期脱离模型能力；但开源框架保留了群体演化的火种。
2. **中国开发者生态可能更快扩散 Agent。** 便宜模型、效率焦虑、开发者规模和高性价比 API，会让 Agent 框架在国内更快渗透。
3. **未来竞争不是“谁有最大模型”，而是谁有最强闭环。** 闭环包括用户使用、Skills 沉淀、环境复现、任务生成、评估、RL、框架迭代和组织学习。
4. **AGI 叙事从智能涌现转向生产力重构。** 访谈里的 AGI 不是抽象意识问题，而是工作被 Agent 系统持续接管、组织和个人重新定义价值的问题。

## 需要保留的批判性判断

这场访谈信息密度高，但也有几个需要谨慎看待的地方：

- 对 OpenClaw 的体验描述带有强烈个人兴奋期色彩，不能直接等同于可复现的行业结论。
- “两年内实现 AGI”是趋势判断，不是严格技术证明，应放在预测语境里理解。
- “体感优先、短期忽略 benchmark”适合范式切换早期，但长期仍必须回到可重复评估，否则容易把产品体验误认为能力跃迁。
- “不太存在管理”的组织观适合高密度研究探索团队，不一定能直接迁移到大规模工程组织。

## 对个人和团队的启发

- 不要只问“哪个模型最强”，要问“我的任务是否有合适的 Agent 框架、记忆、工具、评估和技能沉淀”。
- 把重复性任务、业务流程、判断标准写成 Skills，比单次 prompt 优化更有长期价值。
- 在新范式早期，密集使用、共享案例、快速复盘，比抽象讨论更能形成判断力。
- 对研究团队来说，最关键的资产可能不是一批静态数据，而是一套能持续产生高质量轨迹的环境。
- 对公司来说，内部知识如果不能被 Agent 读取、执行和验证，就无法变成生产力红利。
