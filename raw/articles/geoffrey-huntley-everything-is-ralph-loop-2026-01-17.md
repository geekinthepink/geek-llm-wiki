# everything is a ralph loop

**Source:** https://ghuntley.com/loop/
**Author:** Geoffrey Huntley, 2026-01-17
**Date:** 2026-01-17

---

我一直在思考，我现在构建软件的方式与三年前有多么不同。

不，我说的不是使用 AI 带来的加速，而是更根本层面的方法、技术和最佳实践。

标准的软件实践是像搭 Jenga 一样垂直地一砖一瓦地构建，但现在我把一切都当作**循环（loop）**来处理。你看，Ralph 不仅仅是正向模式（自主构建）或反向模式（净室逆向），它更是一种**心智模式（mindset）**——这些计算机确实是可以被编程的。

作为一名工程师，我依然在场，只是在砖块时代，我是在编程循环，自动化我的工作职能，并消除雇佣人类的需求。

现在每个人都在经历他们的狂热期——就像我当初在正向模式和全自动 AFK 构建软件时一样——但我希望人们能从轨道上回到地面，记住我在原始 Ralph 帖子中说的话：

> 我在旧金山时，每个人似乎都在试图攻克多 Agent、Agent 间通信和多路复用。在这个阶段，这**并不需要**。想想微服务及其所有复杂性。现在，如果微服务（Agent）本身是非确定性的，那会是什么样子？一团糟。

微服务的反面是什么？**单体应用**。一个垂直扩展的单一操作系统进程。Ralph 是单体的。Ralph 在单个仓库中作为单个进程自主运行，每次循环执行一个任务。

**软件现在是陶轮上的粘土**，如果有什么不对，我就把它扔回轮子上重新塑形。

Ralph 是一种编排模式：你分配好所需的底层规格数组，给它一个目标，然后循环执行这个目标。

观察循环过程非常重要，因为这是你个人成长和学习的地方。当你看到失败域时——戴上工程师帽子，解决这个问题，让它永不再发生。

在实践中，这意味着通过提示手动执行循环，或者通过自动化但需要按 Ctrl+C 暂停来进入下一个任务。这仍然是 ralphing，因为 Ralph 的核心是通过上下文工程充分发挥底层模型的能力，而这种模式是**通用的**，可以用于**所有任务**。

另外，我一直在捣鼓一个叫"**The Weaving Loom**"的东西。Loom 的源代码现在可以在我的 GitHub 上找到；但如果你不是 Geoffrey Huntley，请不要使用它。Loom 在我脑海中已经存在了三年（去年开发了各种原型！），它本质上是**进化软件的基础设施**。Gas town 专注于转盘子编排——这是一个完整的 8 级。参见 [Steve Yegge: Welcome to Gas Town](https://steve-yegge.medium.com/welcome-to-gas-town-4f25ee16dd04)。

我正在向 9 级进军：自主循环进化产品并自动优化收入生成。**进化软件**——也被称为软件工厂。

现在存在一个分歧：我们有软件工程师表面上拒绝 AI，或者仅仅通过 Claude Code/Cursor 来加速乐高积木的搭建过程……

但**软件开发已经死了**——我杀死了它。软件现在可以比麦当劳汉堡翻转员的工资更便宜地被开发出来，而且可以在你离开时自主构建。

虽然软件开发/编程已经死了。但我们**迫切需要**具备这些技能的软件工程师，他们理解 LLM 是一种新型可编程计算机。如果你还没有构建自己的编码 Agent——请现在就做。[如何构建编码 Agent：免费研讨会](https://ghuntley.com/)

构建编码 Agent 并不难。300 行代码，运行在一个带有 LLM token 的循环中。你只需要不断向循环投入 token，你就有了一个 Agent。
